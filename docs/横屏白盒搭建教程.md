# Godot 4：1920×1080 横屏三基地推图白盒

本教程对应仓库当前横屏版本。推荐 Godot 4.6.x 标准版，下载仓库 ZIP 后导入 `project.godot`，按 F5 即可运行。先运行已有场景，再对照下面流程学习搭建。

## 第一步：设置窗口

「项目 → 项目设置」搜索以下选项：

| 选项 | 值 |
| --- | --- |
| display/window/size/viewport_width | 1920 |
| display/window/size/viewport_height | 1080 |
| window_width_override / window_height_override | 1280 / 720（桌面预览） |
| display/window/stretch/mode | canvas_items |
| display/window/stretch/aspect | keep |
| display/window/handheld/orientation | Landscape 横屏 |

游戏逻辑始终使用 1920×1080 坐标，按比例缩放。其他比例的设备可能有留边。

## 第二步：创建机甲共用场景

新建 2D 场景，根节点 Node2D 命名 `Unit`。从 FileSystem 把 `scripts/unit_agent.gd` 拖到根节点上挂载，保存为 `scenes/unit.tscn`。

方块、血条、蓄力红圈和护盾直接通过 `_draw()` 绘制，不需要贴图或碰撞体。`team=0` 为蓝方、`team=1` 为红方。三排队形的 `lane` 分别为 0、1、2。

蓝方向右、红方向左。只有处于射程内的同排敌人能被普通攻击命中，技能可以跨排。原型没有寻路或碰撞避让，允许单位重叠。

每台己方机甲保存 `origin_base` 引用，记录由哪座工程基地生产。普攻和击杀都通过它向正确基地返还能量。

## 第三步：创建工程基地场景

新建 Node2D 场景，根节点名 `EngineeringBay`，挂载 `scripts/engineering_bay.gd`，结构：

```text
EngineeringBay (Node2D)
├── SpawnPoint (Marker2D)
└── SpawnTimer (Timer)
```

- SpawnPoint 的 Position 为 **(82,0)**，代表基地右侧出兵口。
- SpawnTimer：Wait Time=4、One Shot 关闭、Autostart 关闭、Process Callback=Physics。
- 根节点 Inspector：Spawn Interval=4，Max Hp=600。
- 保存为 `scenes/engineering_bay.tscn`。

Timer 信号已经在脚本 `setup()` 连接，不要再手动重复连接。基地被摧毁会停止产兵，已经生产的小兵继续战斗；基地节点保留，以便存活小兵仍能找到自己的归属。

## 第四步：创建主场景

新建 Node2D，命名 `Game`，挂载 `scripts/battle_game.gd`，保存为 `scenes/main.tscn`。按 Ctrl+A 添加节点，搭成：

```text
Game (Node2D, battle_game.gd)
├── Battlefield (Node2D, battlefield.gd, Z Index=-2)
├── Units (Node2D, 空容器)
├── EngineeringBays (Node2D)
│   ├── Base1 (engineering_bay.tscn 实例)
│   ├── Base2 (engineering_bay.tscn 实例)
│   └── Base3 (engineering_bay.tscn 实例)
├── WaveManager (Node, wave_manager.gd)
├── SkillManager (Node, skill_manager.gd)
└── UI (CanvasLayer)
    └── HUD (Control, battle_hud.gd)
```

将工程基地场景拖到 EngineeringBays 下，Ctrl+D 复制到三个。分别设置：

| 名称 | Position | Lane |
| --- | --- | --- |
| Base1 | (220,430) | 0 |
| Base2 | (220,540) | 1 |
| Base3 | (220,650) | 2 |

HUD：Position=(0,0)、Size=(1920,1080)、Mouse Filter=Ignore。节点英文名区分大小写，不能随意更名，否则 `$节点路径` 找不到目标。

右侧刷怪坐标由 WaveManager 统一计算，不再需要竖屏版本的 EnemySpawnPoints 节点。第一列敌人 X=1590，后列每隔 55 像素，Y 与三座基地一致。

## 第五步：创建顶部信息和右下角开关

在 HUD 下直接添加这些节点：

| 名称 | 类型 | Position | Size | 初始内容 |
| --- | --- | --- | --- | --- |
| WaveLabel | Label | (760,20) | (400,50) | 1 / 3，字号36 |
| TimerLabel | Label | (760,75) | (400,50) | 01:30，字号34 |
| ResourcesLabel | Label | (1400,25) | (470,60) | 金币 0 宝箱 0，字号28 |
| NoticeLabel | Label | (300,140) | (1320,45) | 操作提示，字号24 |
| ResultLabel | Label | (510,270) | (900,100) | 结算提示，字号44 |
| PauseButton | Button | (40,35) | (100,65) | 暂停 |
| RestartButton | Button | (155,35) | (100,65) | 重开 |
| AutoButton | Button | (1720,945) | (160,75) | 托管：关 |

Label 设置 Horizontal Alignment=Center。AutoButton 勾选 Toggle Mode，默认 Button Pressed 关闭。

创建 Theme 资源，把 `assets/fonts/ntm-ui.otf` 设置为 Default Font，并把 Theme 拖到 HUD 的 Theme 属性。已有主场景已配好。中文字体已打包，不依赖玩家电脑的系统字体。

## 第六步：创建一个圆形按钮和三个六边形头像

在 HUD 下创建四个 **Button**，均挂载 `scripts/portrait_button.gd`：

| 名称 | Position | Size | Caption | Round Shape |
| --- | --- | --- | --- | --- |
| ShipButton | (565,825) | (150,150) | 母舰法宝 换行 就绪 | 开启 |
| Portrait1 | (785,825) | (150,150) | 1号工程基地 换行 鸾鸟轰炸 | 关闭 |
| Portrait2 | (1005,825) | (150,150) | 2号工程基地 换行 玄女点杀 | 关闭 |
| Portrait3 | (1225,825) | (150,150) | 3号工程基地 换行 承影护盾 | 关闭 |

按钮脚本用几何绘制圆形、六边形与金色外框。普通 Button 的 Text 留空，文字使用脚本导出字段 Caption。

三组绿色血条和黄色能量条由 `battle_hud.gd` 的 `_draw()` 绘制：血量条 Y=992，能量条 Y=1017，每条宽150高16，X分别785、1005、1225。它们直接读取对应基地的真实数值，便于第一版避免繁琐的控件绑定。

按钮连接已写在 HUD 的 `setup()`：

```gdscript
$Portrait1.pressed.connect(game.skills.cast_luanniao_bombardment)
$Portrait2.pressed.connect(game.skills.cast_xuannv_strike)
$Portrait3.pressed.connect(game.skills.cast_chengying_shield)
```

保留这些代码时不要在 Signals 面板重复连接。每个头像只能消耗自己的基地能量。能量满100时外框变金色；如果没有合法目标（例如没有蓄力精英），相应技能仍不可释放且不会扣能量。

## 第七步：理解能量和技能

- 每台己方小兵普攻：所属基地 +2。
- 每次击杀敌人：造成致命伤害的所属基地 +20。
- 1号轰炸和2号点杀的技能击杀：额外 +5，合计 +25，返还给施法基地。
- 每座基地能量独立，上限100，不在基地之间转移。
- 托管默认关闭，金色高亮只提示，不会自动释放。
- 开启托管后每0.25秒检查一次，按「玄女打断 → 承影护盾 → 鸾鸟轰炸」顺序尝试合法技能；波间不自动消耗能量。

| 按钮 | 默认效果 |
| --- | --- |
| 1号鸾鸟 | 消耗基地1的100能量，对全场敌人造成120伤害 |
| 2号玄女 | 消耗基地2的100能量，锁定即将放招的蓄力精英，300伤害，打断并眩晕2秒 |
| 3号承影 | 消耗基地3的100能量，为当前全部存活己方小兵加150护盾，持续5秒 |
| 圆形母舰 | 本版暂定全场60伤害、独立20秒冷却，不消耗基地能量且不返能；始终手动点击 |

母舰效果是为原型补充的可玩默认值。可在 `BattleGame.cast_mothership()` 修改。三个基地技能参数在 SkillManager 的 Inspector 中调整。

## 第八步：三波、计时、结算

- 全局总时限90秒，顶部从01:30倒数；换波不重置。
- 第1波每排2个敌人，共6个；第2波每排3个，共9个；第3波每排4个，共12个。
- 从第2波起每排最后一个是精英，400血，每8秒开始3秒蓄力；期间红圈渐深。未打断则对220范围造成60伤害。
- 清波后等待2秒；WaveManager只创建新敌人，不重建 Game，不清空 Units，也不重置三个基地对象。
- 保留幸存小兵、实际血量和剩余护盾时间、基地血量、三个能量值与生产进度。波间小兵照常移动、基地照常产兵。
- 第3波全灭：胜利、宝箱+1；每击杀一个敌人金币+10。金币与宝箱是本局演示计数，重开归零。
- 90秒耗尽或三座基地全部被摧毁：失败。结算后停止战斗和产兵，点击重开重新开始。

## 第九步：伤害跳字和后续替换美术

`BattleGame.deal_damage()` 记录伤害，`add_damage_text()` 生成寿命0.85秒的浮动文字，`_draw()` 让它向上漂移并渐隐。数字显示实际扣除的HP，例如 -10、-120、-300，不会为了模仿截图固定显示 -4344。护盾完全挡住时显示 -0。

本版复现参考图的横版信息分区与操作位置，建筑、机甲、按钮和场地均为纯色白盒。后续把 Sprite2D 加到单位或建筑场景中，保留脚本和红圈；先验证机制，再换贴图。

## 常见问题

- 找不到节点：检查名称和层级，尤其是 HUD 的四个头像按钮、工程基地的 SpawnPoint 与 SpawnTimer。
- 头像金色却点不了：检查目标条件，或是否暂停、基地已被摧毁、战斗已结束。
- 只有一座基地能量增加：小兵还未接敌，或手工生成的小兵没设置 origin_base；正常产兵函数会自动绑定。
- 中文缺字：修改界面文字后，需要更新字体子集。原型已包含当前用字；Linux环境可使用 tools/build_font.py 和 FontTools 重新生成。
- 网页不是新版：等待仓库 Actions 的最新部署变绿，再刷新页面。

## 素材版更新

当前工程已接入参考图加工素材，节点结构和所有战斗规则不变。新增 `scripts/art_assets.gd` 负责共享图集与区域映射：

- `assets/art/sprite_atlas.png`：12个透明元素，区域表在 atlas_regions.json。
- `assets/art/battle_background.png`：横屏战场背景。
- UnitAgent 的 `art_key()` 根据阵营、基地编号和波次选择英雄、机械犬、炮台或精英贴图。
- 底部四个按钮及 PauseButton 挂载 portrait_button.gd，并设置 Art Key 字段；主场景已配置。
- Battlefield 直接绘制背景；基地绘制hangar，血量和能量继续读取真实逻辑对象。
- 头像变灰与金色高亮由状态控制，原有技能函数不变。

素材为原生图像编辑工具根据用户参考整理和补绘的版本，未宣称原图无损切分。角色使用静态贴图加程序轻摆。来源与限制详见 assets/art/PROVENANCE.md。
