# 零基础搭建：Godot 4，540×960 双路策略白盒

建议先导入随附项目并按 F5 跑起来，再照着下面的流程熟悉节点。要练习完全手工搭建，可另建一个空项目，把本包的 `scripts` 文件夹复制进去，按以下顺序创建三个场景。脚本之间互相引用，尚未完成场景时可能暂时报错，全部节点和路径齐全后再运行。

Godot 中的简单对应关系：**节点**是一个对象；**场景**是一组保存好的节点，也可以反复实例化；**脚本**决定节点的行为；右侧 **Inspector（检查器）** 用来改属性。场景树里的英文名称区分大小写。

## 1. 创建项目并设置竖屏

1. 打开 Godot 4 标准版。项目管理器选择「新建项目」，项目名可填「南天门计划」，渲染器选择 **Compatibility（兼容）**。
2. 打开「项目 → 项目设置」，搜索 `viewport_width`，设置 540；`viewport_height` 设置 960。
3. 搜索 `window_width_override` 和 `window_height_override`，分别设为 540、960。
4. 搜索 `stretch`，将 Mode 设置为 `canvas_items`、Aspect 设置为 `keep`。
5. 搜索 `orientation`，设置为 `Portrait`（竖屏）。这是移动端配置，桌面窗口仍使用上述尺寸。
6. 在项目文件夹里创建 `scripts`、`scenes` 文件夹，把压缩包的七个 `.gd` 文件放到 `scripts` 下。

已有项目用户：随附 `project.godot` 已设置这些选项，不需要再改。

## 2. 创建蓝色 / 红色单位共用场景

1. 按 **Ctrl+N** 新建场景，选择「2D 场景」，根节点为 `Node2D`。
2. 把根节点重命名为 **`Unit`**。
3. 从左下 FileSystem 中，把 `scripts/unit_agent.gd` 拖到场景树的 `Unit` 节点上。这就是「挂载脚本」。
4. 按 **Ctrl+S**，保存为 **`res://scenes/unit.tscn`**。

此场景只有一个节点。方块、血条、红圈和护盾通过脚本的 `_draw()` 绘制，所以不用创建 Sprite2D、CollisionShape2D 或导入图片。编辑器中暂时看不到方块是正常的，运行后才绘制。

同一个场景通过 `configure()` 的参数决定敌我：蓝方 `team = 0`，红方 `team = 1`；`lane = 0` 是左路，`lane = 1` 是右路。`is_elite = true` 时为大一号的红色精英。

## 3. 创建工程舱场景

再按 Ctrl+N 创建 2D 场景，根节点重命名为 **`EngineeringBay`**，挂载 `scripts/engineering_bay.gd`。

选中根节点，按 **Ctrl+A** 添加子节点，最终结构如下：

```text
EngineeringBay  (Node2D，挂 engineering_bay.gd)
├── SpawnPoint  (Marker2D)
└── SpawnTimer  (Timer)
```

依次设置：

| 节点 | 属性 | 值 |
| --- | --- | --- |
| SpawnPoint | Transform → Position | X=0，Y=-46 |
| SpawnTimer | Wait Time | 4 |
| SpawnTimer | One Shot | 关闭 |
| SpawnTimer | Autostart | 关闭；由主场景启动 |
| SpawnTimer | Process Callback | Physics |
| EngineeringBay | 脚本导出字段 Spawn Interval | 4 |

保存为 **`res://scenes/engineering_bay.tscn`**。

这里的 Marker2D 相当于「出兵坐标」。Timer 每到 4 秒会触发一次 timeout 信号，脚本已经负责连接并生成机甲，**不需要在编辑器重复连 timeout**。

## 4. 创建主场景和左右两路

新建 2D 场景，根节点重命名为 **`Game`**，挂载 `scripts/battle_game.gd`，保存为 **`res://scenes/main.tscn`**。

选中 Game，逐个添加下列节点。普通分组节点选 Node2D，管理器选 Node：

```text
Game  (Node2D，battle_game.gd)
├── Battlefield  (Node2D，battlefield.gd)
├── Units  (Node2D，不挂脚本)
├── EngineeringBays  (Node2D)
│   ├── LeftBay  (engineering_bay.tscn 的实例)
│   └── RightBay (engineering_bay.tscn 的实例)
├── EnemySpawnPoints  (Node2D)
│   ├── LeftSpawn  (Marker2D)
│   └── RightSpawn (Marker2D)
├── WaveManager  (Node，wave_manager.gd)
├── SkillManager (Node，skill_manager.gd)
└── UI  (CanvasLayer)
    └── HUD  (Control，battle_hud.gd)
```

具体操作：

1. 选中 `Battlefield`，挂载 `battlefield.gd`，将 **Ordering → Z Index** 设为 **-1**，防止背景盖住单位。
2. 选中 `EngineeringBays`，从 FileSystem 把 `engineering_bay.tscn` 拖进场景树，命名为 `LeftBay`。
3. 设置 LeftBay 的 Position 为 **(155, 760)**，脚本导出字段 `Lane` 设为 **0**。
4. 选中 LeftBay，按 **Ctrl+D** 复制，命名为 `RightBay`，Position 改为 **(385, 760)**，`Lane` 改为 **1**。
5. 在 EnemySpawnPoints 下添加两个 Marker2D：LeftSpawn 为 **(155, 200)**，RightSpawn 为 **(385, 200)**。
6. 给 WaveManager 挂 `wave_manager.gd`；给 SkillManager 挂 `skill_manager.gd`。
7. 创建 CanvasLayer 命名 UI，再添加 Control 命名 HUD，挂 `battle_hud.gd`。
8. HUD 的 Position 设为 **(0,0)**，Size 设为 **(540,960)**，Mouse → Filter 设为 **Ignore**。

`Units` 必须为空，它是运行时生成的所有机甲的父节点。不要把它命名为 Unit，否则 `$Units` 找不到路径。

## 5. 创建底部技能按钮与文字

在 HUD 下添加以下节点，名称必须一致：

```text
HUD  (Control)
├── TitleLabel  (Label)
├── WaveLabel   (Label)
├── UnitLabel   (Label)
├── PauseButton (Button)
├── RestartButton (Button)
├── NoticeLabel (Label)
├── BottomPanel (Panel，可选装饰)
├── EnergyLabel (Label)
├── EnergyBar   (ProgressBar)
└── SkillButtons (HBoxContainer)
    ├── LuanniaoButton  (Button)
    ├── XuannvButton    (Button)
    └── ChengyingButton (Button)
```

使用固定画布做第一版，在各 Control 的 Layout / Transform 中设置 Position 和 Size。不要把下面这些节点改成别的父节点，脚本使用相对路径查找。

| 名称 | 类型 | Position | Size | 初始文字 / 设置 |
| --- | --- | --- | --- | --- |
| TitleLabel | Label | (24,18) | (366,36) | 南天门计划 · 白盒演练；字号 25 |
| WaveLabel | Label | (24,62) | (492,27) | 第1波；字号 17 |
| UnitLabel | Label | (24,93) | (492,25) | 单位统计；字号 13 |
| PauseButton | Button | (420,22) | (48,34) | 暂停；字号 12 |
| RestartButton | Button | (473,22) | (49,34) | 重开；字号 12 |
| NoticeLabel | Label | (24,119) | (492,27) | 战术提示；字号 12；Autowrap 开启 |
| BottomPanel | Panel | (16,813) | (508,131) | Mouse Filter=Ignore |
| EnergyLabel | Label | (30,825) | (180,29) | 能量 0 / 100；字号 17 |
| EnergyBar | ProgressBar | (220,833) | (288,14) | Min=0、Max=100；关闭 Show Percentage |
| SkillButtons | HBoxContainer | (28,865) | (484,64) | Theme Overrides → Constants → Separation=8 |

三个技能按钮是容器的子节点，其位置由容器自动安排。选中每个按钮，将 **Container Sizing → Horizontal** 设为 **Fill + Expand**。字号设为 13，文字可换行：

- LuanniaoButton：`鸾鸟轰炸` 换行 `群伤 / 100能量`。
- XuannvButton：`玄女点杀` 换行 `打断 / 100能量`。
- ChengyingButton：`承影护盾` 换行 `保护 / 100能量`。

在 Inspector 中先勾选三个按钮的 **Disabled**。游戏会根据能量、目标与暂停状态自动更新。

### 按钮怎样挂技能？

三个独立函数在 `scripts/skill_manager.gd`：

```gdscript
cast_luanniao_bombardment()
cast_xuannv_strike()
cast_chengying_shield()
```

`battle_hud.gd` 的 `setup()` 已有下面三行：

```gdscript
skill_one.pressed.connect(skills.cast_luanniao_bombardment)
skill_two.pressed.connect(skills.cast_xuannv_strike)
skill_three.pressed.connect(skills.cast_chengying_shield)
```

这相当于把每个按钮的「按下」事件接到一个独立函数。**保留这些代码时，不要再去 Signals 面板手动连接同一个技能。** 如果以后想练习面板连接，先删除对应 connect 代码，再在 Button 的「节点 / Signals → pressed」中，选择 SkillManager，填入对应函数名。

## 6. 第一次运行

1. 保存全部文件，按 **F5**。
2. 若提示选择主场景，选 `scenes/main.tscn`。
3. 刚开始，上方两路共 4 个红色方块向下移动。
4. 第 4 秒，两座工程舱各生成一个蓝色方块；之后各自每 4 秒继续生成。
5. 同路线的蓝红方块接近后停下，每秒普攻一次。
6. 每次蓝方普攻 +2；敌人死亡 +20；能量最高 100，达到后不会自动释放技能。
7. 手动点击鸾鸟，可攻击两路敌人。每个轰炸击杀返能 **20 + 5 = 25**。
8. 从第 2 波开始，会出现大一号的红色精英。它每隔 8 秒开始 3 秒蓄力，停止走动，脚下红圈渐深。
9. 蓄力期间且能量满 100，玄女按钮才点亮。点击后造成 300 伤害，取消蓄力，存活目标眩晕 2 秒。
10. 承影给当前存活己方机甲增加青色护盾，先扣护盾再扣血，5 秒后消失。
11. 当前波最后一个敌人死亡后，顶部显示 2 秒倒计时，然后从上方两路出下一波。己方机甲、伤残血量和剩余能量不会重置。

想立即练习打断：选择 WaveManager，将 `Elite From Wave` 临时改成 1；选择 SkillManager，将 `Strike Damage` 临时改小一点，便于观察精英存活后的眩晕。能量依然必须靠战斗积累到 100。

## 7. 每个脚本该看哪里

- **工程舱**：`engineering_bay.gd` 的 `_on_spawn_timer_timeout()`，看生成单位的调用。
- **自动战斗**：`unit_agent.gd` 的 `tick()`，按「护盾计时 → 眩晕 → 蓄力 → 普攻 → 移动」顺序执行。
- **能量**：`battle_game.gd` 的 `perform_basic_attack()`、`deal_damage()`、`add_energy()`，看 +2、+20 和 100 上限。
- **三个技能**：`skill_manager.gd`，先检查合法目标，再消费 100，最后应用效果。
- **波次**：`wave_manager.gd` 的 `notify_enemy_died()`，本波 ID 全部移除后才进入等待。
- **红圈**：`unit_agent.gd` 的 `_draw()`，使用 `1 - charge_remaining / elite_charge_duration` 得到蓄力进度，改变红色透明度和圆弧长度。

本版没有寻路系统，只在两条固定路线内上下移动。没有碰撞组件，判定方式是「同路线 + 距离在射程内」，所以不会出现新手常遇到的物理层和碰撞遮罩配置问题。

## 8. 常见问题

**提示 Node not found / 找不到节点**：检查名称与父子层级。`SpawnPoint` 和 `SpawnTimer` 必须是工程舱的子节点，三个按钮必须在 `UI/HUD/SkillButtons` 下。

**蓝方只有一路出兵**：检查 RightBay 的 Lane 是否为 1，位置是否为 (385,760)。确认没有误删它的 SpawnTimer。

**主场景里看不见方块**：单位运行时才创建。按 F5，等待 4 秒看蓝方产兵。纯色图形由脚本绘制，不会有贴图文件。

**能量满了，玄女还是灰色**：只有精英正在蓄力时才可点杀。这是目标条件；没有目标时不会浪费能量。

**点击技能没有声音或复杂动画**：本阶段只有线条、圆圈与数值反馈，还没有接入音效或美术。

**暂停后点不了技能，但能点继续**：HUD 使用 Always 模式继续接收按钮输入，战斗、产兵、护盾和波次等待会一起暂停，这是预期行为。

**队伍走到顶端后停住**：那里是白盒备战线，让幸存单位保持在画面内等待下一波。本阶段没有基地胜负逻辑，也没有让单位走出屏幕后消失。

**想放真实图片**：先保持此版本正常运行，再向 Unit 场景添加 Sprite2D，逐项替换 `_draw()` 的方块。保留红圈和青色护盾的代码，不需要先做复杂动画。

**手机安装包在哪里**：本包是编辑器工程，不是 APK。先在编辑器运行机制，确认后再安装 Godot Android 导出模板及 Android SDK，处理真实设备适配和打包。
